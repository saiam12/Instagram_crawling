# 패션·화장품 16시간 수집 및 재수집 설계

## 목표

기존 기본 Reel 데이터와 완전히 분리된 패션·화장품 데이터 세트를 최대 16시간 동안 운용한다. 신규 Reel 탐색은 시작 후 첫 7시간에만 수행하고, 남은 최대 9시간은 재수집만 수행한다. 따라서 마지막 신규 Reel도 `+8시간` 스냅샷을 15시간 안에 마칠 수 있으며, 이번 실행에서 생긴 모든 Reel이 여섯 번째 스냅샷까지 끝나면 즉시 정상 종료한다.

| 순서 | 최초 수집 후 경과 | 작업 |
| --- | --- | --- |
| 1 | 즉시 | 최초 수집 |
| 2 | 30분 | 재수집 1회 |
| 3 | 1시간 | 재수집 2회 |
| 4 | 2시간 | 재수집 3회 |
| 5 | 4시간 | 재수집 4회 |
| 6 | 8시간 | 재수집 5회 및 종료 |

신규 탐색은 시작 후 첫 7시간 동안만 30분 단위 창으로 실행한다. 첫 창은 패션, 다음 창은 화장품으로 번갈아 실행하므로 각 도메인은 일곱 번의 신규 탐색 창을 갖는다. 각 활성 창은 키워드 다섯 개에서 키워드당 최대 50개의 후보를 확인하고, 조건을 통과한 신규 Reel을 최대 300개 저장한다. 최초 수집 후보는 수집 시점 기준 업로드 후 30일 이내여야 하며, 이미 최초 수집된 Reel의 재수집에는 이 업로드 경과일 제한을 적용하지 않는다. 7시간 시점부터 종료 또는 모든 여섯 번째 스냅샷 완료 시점까지는 신규 탐색을 하지 않는다. 중복·비공개·Instagram 응답 실패는 상태 파일과 콘솔에 남긴다.

## 분리된 데이터와 공개 파일

원본 이력은 아래 경로에 분리 저장한다. 기존 `data_web/.collector/`, `reels.*`, `users.*`와도, 두 도메인끼리도 이력을 공유하지 않는다.

- `python_version/data_web/.datasets/fashion/.collector/`
- `python_version/data_web/.datasets/beauty/.collector/`

공개 산출물은 `python_version/data_web/`에 만든다.

- `fashion_reels.csv`, `fashion_reels.json`, `fashion_reels.xlsx`
- `fashion_users.csv`, `fashion_users.xlsx`
- `fashion_collector_status.json`
- `beauty_reels.csv`, `beauty_reels.json`, `beauty_reels.xlsx`
- `beauty_users.csv`, `beauty_users.xlsx`
- `beauty_collector_status.json`

두 도메인의 Reel 공개 형식은 기존 `reels.xlsx`의 열 순서와 재수집 표시 방식을 공유한다. 두 User CSV/XLSX는 수집 회차별 행 이력과 `follower_count_change` 열을 공유한다. 기존 기본 산출물은 이 작업에서 수정하지 않는다.

모든 Reel 수집은 영상 길이를 정수 초 단위의 `video_duration_seconds`로 저장한다. Instagram 응답에서 값을 확인할 수 없으면 빈칸으로 두고 해당 Reel 저장은 계속한다. 패션·화장품 공개 Reel 파일은 최초 수집과 재수집을 각각 별도 행으로 추가해 기존 행을 변경하지 않는다. 팔로워 수를 수집할 때는 같은 프로필 응답의 `biography`(사용자가 작성한 프로필 소개글)를 동일한 User 이력 행에 함께 기록한다. 기본 User 공개 파일에는 직전 팔로워 수집 시각과의 `days_since_previous`를 표시한다. 패션·화장품 공개 Reel/User 파일은 짧은 재수집 간격을 분명하게 보이도록 일 단위 대신 `hours_since_previous`를 사용하며, 값은 `+0.5hour`, `+4hour`처럼 표기한다. 기본 Reel 공개 파일의 기존 일 단위 표기는 바꾸지 않는다.

## 명령 인터페이스

`collector.ps1` 및 Python 실행기에 세 예약 명령을 제공한다. `fashion`은 패션만, `beauty`는 화장품만, `fashion-beauty`는 패션·화장품 두 도메인을 30분 창마다 교대로 운용한다.

```powershell
.\collector.ps1 fashion-beauty --duration-hours 16 --discovery-hours 7 --new-items-per-window 300 --max-new-items-per-window 300 --max-upload-age-days 30 --discovery-interval-minutes 30
```

기본값은 위의 패션·화장품 운영값이다. 별도 키워드 옵션이 없으면 내장 키워드를 순환한다. 각 도메인은 활성 창마다 다섯 개 키워드 묶음을 사용하고, 다음 활성 창에서 다음 묶음의 첫 키워드부터 시작한다. 단독 명령은 해당 도메인을 매 창 탐색하고, `fashion-beauty`는 패션과 화장품을 창마다 교대한다. `--fashion-hashtag-query` 또는 `--beauty-hashtag-query`를 주면 해당 도메인의 내장 키워드를 대체한다.

## 스케줄러와 수집 순서

기존 로그인 브라우저 프로필은 하나의 지속 컨텍스트로만 열어 재사용한다. 같은 도메인 출력에는 하나의 작업만 쓰며, 패션·뷰티는 각자 독립 데이터셋·릴스 탭·정확 지표 조회 탭을 사용한다. 두 도메인의 기한 재수집이 동시에 있으면 신규 탐색보다 먼저 병렬 실행한다.

1. 시작 시 두 원본 이력을 읽어 각 URL의 최초 수집 시각과 완료 스냅샷 수를 복원한다.
2. 매 분마다 최초 수집 시각 기준으로 두 도메인의 기한 재수집 작업을 계산한다.
3. 기한이 지난 재수집은 우선 처리하되, 같은 도메인의 URL을 최대 50개씩 한 브라우저 세션에서 직렬 실행한다. 패션과 뷰티 모두 기한이면 공유 로그인 브라우저의 독립 탭에서 두 묶음을 병렬 실행한다. 실패한 묶음은 지수적 대기 후 같은 수집 차수로 다시 시도한다.
4. 시작부터 7시간까지는 30분 창을 패션, 화장품, 패션, 화장품 순서로 교대한다. 활성 도메인의 현재 다섯 개 키워드 묶음으로 새 URL을 발견하고, 중복 제거와 수집 시점 기준 업로드 후 30일 이내 필터 뒤 신규 수집을 진행한다. 키워드당 후보는 최대 50개이고 창당 저장 상한은 300개다.
5. 새 URL마다 최초 수집이 성공한 때의 절대 시각으로 `+30m`, `+1h`, `+2h`, `+4h`, `+8h` 작업을 한 번씩 예약한다. 재수집에는 업로드 경과일 제한을 적용하지 않는다. 직전 재수집 시각을 기준으로 누적하지 않는다.
6. 시작 후 7시간부터 최대 16시간 종료 시각까지 신규 탐색을 중지하고, 두 도메인의 8시간 스냅샷을 포함한 기한 재수집만 마무리한다. 이번 실행에서 시작된 Reel의 여섯 번째 스냅샷이 모두 저장되면 즉시 종료한다. 8시간 스냅샷을 저장한 Reel은 다시 예약하지 않는다.

Instagram에서 응답이 늦거나 기한 작업이 밀릴 때는 재수집을 먼저 소화하고 활성 도메인의 신규 탐색을 지연한다. 신규 수집이 300개에 도달한 창에서는 다음 30분 경계까지 신규 요청을 발행하지 않는다. 병렬 처리는 서로 다른 도메인의 독립 탭에만 적용하고, 각 도메인 안의 Reel 요청은 직렬로 유지한다.

## 요청 속도와 상태 복구

- Reel 요청은 한 번에 하나만 수행하고 성공 뒤 최소 2초를 둔다.
- 팔로워 수 조회는 기존 8초 간격과 캐시를 그대로 적용한다.
- 스케줄러가 재시작되어도 원본 이력으로 인해 중복 스냅샷이나 잘못된 회차가 생기지 않는다.
- 각 도메인 상태 파일에는 시작 시각, 신규 탐색 종료 예정 시각, 전체 종료 예정 시각, 현재 키워드 묶음, 최초 수집의 최대 업로드 경과일 30일, 현재 30분 창의 신규 목표/성공/업로드 경과일 필터/실패/상한 도달 여부, 기한 재수집/지연 수, 마지막 오류를 기록한다.
- 종료 시 또는 주기적 체크포인트마다 해당 도메인의 공개 산출물을 원자적으로 다시 만든다.

## 검증 기준

- 시간 계산 단위 테스트: 각 최초 수집 시각에서 정확히 다섯 번의 재수집 시각과 여섯 개의 총 스냅샷을 계산한다.
- 임시 두 원본 이력으로 재시작 복구와 도메인 간 기한 재수집 우선순위를 검증한다.
- 최초 수집에서 30일 초과 후보가 제외되고, 같은 Reel의 재수집은 30일 제한을 받지 않음을 검증한다.
- 패션·화장품 공개 CSV·JSON·XLSX의 헤더와 레코드 수가 일치하고 기존 Reel 형식과 동일함을 검증한다.
- 기본 `reels.*`, `users.*`와 다른 도메인의 출력에 실행 전후 변경이 없음을 검증한다.
- `video_duration_seconds`가 숫자 초로 저장되고, 누락된 길이가 Reel 저장 실패로 이어지지 않음을 검증한다.
- 팔로워 수집 User 이력에 `biography`와 직전 수집 대비 일 단위 경과값이 남고, 패션·화장품 공개 Reel/User 파일에는 시간 단위 경과값이 남음을 검증한다.
- 짧은 기간·작은 신규 목표로 실행하는 드라이런 명령을 검증한다.
