# Google Sheets 공용 키 풀

`reel_analyzer.py`는 기본적으로 공용 풀을 사용합니다. 아래 설정을 마치기 전에는
시트 연결 설정을 안내하고 실행을 중단합니다. 로컬 풀로 자동 우회하지 않습니다.

## 선택 순서

각 릴스 다운로드가 끝나고 Gemini 분석을 시작할 때마다 다음 과정을 반복합니다.

1. 로컬에 키가 있고 모델이 허용된 조합만 서버에 별칭으로 전달합니다.
2. 서버는 `프로젝트 설정`과 `요청 기록`을 읽고 사용중, 일일 소진, RPM 초과,
   일시 대기인 프로젝트/모델을 제외합니다.
3. 후보를 무작위로 최대 2개 뽑아 같은 ScriptLock 안에서 둘 다 `후보 예약`으로 기록합니다.
4. 당일 요청 **횟수**가 적어 잔여량이 많은 후보를 `사용중`으로 남기고 나머지는 `선택 해제`로 기록합니다.
   잔여량이 같으면 높은 Flash 모델을 사용합니다(3.8 → 3.6). 후보가 하나뿐이면 그 후보를 사용합니다.
5. Python이 선택된 키로 분석합니다. 영상/분석 본문은 Apps Script에 보내지 않습니다.
   실제 API 키는 명시적인 동기화 명령에서만 전송되어 스크립트 속성에 저장됩니다.
6. 성공/실패/중단 시 결과를 기록하고 사용중 상태를 해제합니다. 429는 제한 종류도 기록합니다.
7. 다음 릴스와 API 오류 후 재시도 모두 새 요청 ID로 다시 추첨합니다.

실행 중인 Python은 1분마다 heartbeat를 보냅니다. 마지막 heartbeat가 10분을 넘긴 예약은
비정상 종료된 것으로 보고 `사용중` 잠금에서 제외합니다.

공용 풀의 잠금을 공유하려면 **같은 Apps Script 배포**를 사용해야 합니다.
프로젝트/모델이 같으면 키가 여러 개여도 같은 예약/사용량으로 취급합니다.
분석 기본 모델은 3.6 Flash이며 3.8 Flash도 명시적으로 선택할 수 있습니다. 3.5/3.7 Flash는 제외하고 기존 행은 동기화 시 중지합니다. Antigravity 가이드는 별도 모델 행과 예약으로 기록하며 Flash Lite는 거부합니다.

## 시트 설정

각 탭의 1~4행은 안내, 5행은 머리글, 6행부터 데이터입니다.

`프로젝트 설정`: A 키 별칭 / B 담당자 / C 모델 / D RPM / E RPD /
F 사용 여부(`사용` 또는 `중지`) / G 비고 / H 초기 집계일 / I 초기 사용량.

- A열은 로컬 `.env`의 `GEMINI_API_KEYS`에 적은 별칭과 정확히 일치해야 합니다.
- `.env`의 `GEMINI_API_KEY_OWNERS`에 `{키별칭:담당자,...}`를 지정하고
  `.\.venv\Scripts\python.exe reel_analyzer.py --sync-key-pool` (실행 위치: `analyzers`)을 실행하면 공유 키와 설정이 자동 병합됩니다.
  중앙에 없는 키는 `GEMINI_API_KEY_OWNERS`의 담당자로 등록하며, 매핑이 없으면
  현재 실행자인 `GEMINI_POOL_USER`를 담당자로 사용합니다. 이후 키 값은 현재 담당자만 갱신할 수 있습니다.
  중앙에만 있거나 값·담당자가 변경된 키는 로컬 `.env`에 추가·갱신됩니다.
  중앙에 등록된 키 별칭은 `acct1` 형식으로 표시하고, 담당자는 키별 매핑 값으로 표시됩니다.
  `GEMINI_API_KEY_OWNERS`를 생략한 경우, 모든 공유 키가 한 담당자 소유이고
  키 값은 그대로인 상태에서 `GEMINI_POOL_USER`만 바꾸면 담당자 표시명을 일괄 변경합니다.
  요청 기록에도 같은 별칭을 적용해 사용량을 연속해서 집계합니다.
  새 별칭에는 Flash 3.6/3.8, Antigravity, Embedding 2 행이 추가됩니다. RPM 기본값은 5이고 RPD는 아래 작업별 정책을 따릅니다.
  기존 지원 모델 행의 `중지`는 동기화 후에도 유지됩니다. 다시 사용하려면 관리자가 해당 행을 `사용`으로 바꿉니다.
  로컬에서만 키를 지우면 다음 동기화에서 중앙값이 다시 추가됩니다.
  처음 연결할 때는 `GEMINI_API_KEYS="{}"`로 두고 실행해도 중앙의 공유 키를 내려받을 수 있습니다.
- 현재 풀은 키 별칭을 프로젝트 식별자로 사용합니다. 한 Google 프로젝트에서는 대표 키 하나와 별칭 하나만 등록하세요.
  같은 프로젝트의 여러 키를 다른 별칭으로 등록하면 실제 공유 할당량을 각각 계산하게 됩니다.
  같은 별칭/모델 행을 중복 작성하면 설정 오류로 중단합니다. 프로젝트는 키 문자열에서 자동 식별되지 않습니다.
- 현재 사용하는 Flash 모델의 한도는 RPM 5 / RPD 20으로 설정했습니다. 실제 한도는 각 Google 프로젝트에서 확인해야 합니다.
- H/I열은 공용 기록 시작 **직전** AI Studio에 표시된 사용량을 초기값으로 넣는 선택 항목입니다.
  H열은 한국 날짜를 텍스트 `YYYY-MM-DD`로 입력합니다. 입력할 때 앞에 작은따옴표를 붙여도 됩니다.
  빈 초기값은 0으로 취급하므로 실제 외부 사용량이 있으면 직접 반영해야 합니다.
  운영 중 총사용량을 초기값으로 덮어쓰면 공용 기록과 이중 집계되므로 하지 마세요.

`요청 기록`은 A:Q 열을 사용하며 P열은 `후보 선택 전 요청 수`, Q열은 `후보 선택 전 잔여량`입니다.
선택된 예약부터 요청 수를 1회 차감하며 미선택 후보는 차감하지 않습니다.
업로드 오류 등 실제 추론 전에 실패한 경우도 보수적으로 1회 집계합니다.
토큰 수는 성공 응답에 값이 있는 경우만 기록하며 토큰 잔여량을 보장하지 않습니다.

`사용 현황`은 서버 요청 시 갱신되는 조회용 표입니다. 이 탭을 수동 수정해도 예약/사용량은 바뀌지 않습니다.
추정 잔여량의 일일 카운트는 한국시간 자정에 초기화되며, 진행 중 예약은 날짜가 바뀌어도 유지됩니다.
재시도 가능 시각은 표시하지 않고, 마지막 사용 시각을 날짜 없이 한국시간 `HH:mm:ss`로 표시합니다.
마지막 갱신은 날짜 없이 한국시간 `HH:mm:ss`로 표시됩니다.
`사용 중 사용자`에는 해당 예약을 만든 `GEMINI_POOL_USER`가 표시됩니다.

## Apps Script 설치/배포

1. 공용 풀은 `Code.js`의 `SHEET_ID`에 지정된 동일한 Google Sheets를 사용합니다.
   새 시트로 별도 운영할 때만 상단 `SHEET_ID`를 새 시트 ID로 변경하고
   `프로젝트 설정`, `요청 기록`, `사용 현황` 탭을 만듭니다.
   각 탭은 1~4행을 안내용으로 비우고, 5행에 아래 머리글을 넣습니다. 실제 데이터는 6행부터 기록됩니다.
   사용량을 집계하는 운영 시트의 기록 행은 보존합니다.
2. 확장 프로그램 → Apps Script를 열어 이 폴더의 `Code.js` 내용을 `Code.gs`에 넣고 저장합니다.
3. 프로젝트 설정 → 스크립트 속성에 `POOL_TOKEN`을 추가합니다.
   시트 ID는 코드의 `SHEET_ID` 상수로 지정하며, 같은 이름의 스크립트 속성은 필요하지 않습니다.
   시트를 변경할 경우 대상 URL의 `/spreadsheets/d/`와 다음 `/` 사이 ID를 상수에 넣습니다. 전체 URL을 넣지 않습니다.
   `POOL_TOKEN`은 아래와 같이 설정합니다.
   32자 이상의 무작위 비밀값을 사용하고 로컬 `.env`의 `GEMINI_POOL_TOKEN`과 맞춥니다.
   키 원문이나 이 토큰을 시트 셀/코드/Git에 넣지 마세요.
   동기화된 키는 `GEMINI_SHARED_KEYS` 스크립트 속성에 자동 저장됩니다. 이 값을 직접 만들 필요는 없습니다.
   `GEMINI_POOL_TOKEN`을 아는 사용자는 모든 공유 키를 내려받을 수 있으므로 접근을 허용할 사용자에게만 전달하세요.
4. 웹 앱으로 배포합니다. Python의 무인 호출 방식은 소유자 권한으로 실행하는 웹 앱을 사용하며,
   접근 가능한 엔드포인트에서 본문의 토큰을 검증합니다. 공개 접근 배포 및 Google 권한 동의는
   사용자가 해당 접근 범위를 확인하고 승인한 뒤 진행해야 합니다.
5. 배포된 `/exec` URL을 `.env`에 넣습니다. `/dev`는 사용하지 않습니다.
6. 같은 공용 풀에 연결할 때는 동일한 배포 URL/토큰과 서로 구분되는 사용자 별칭을 사용합니다.
   코드 변경 시 웹 앱 배포 버전도 갱신해야 합니다.

각 블록은 해당 탭의 **A5**에 붙여넣을 수 있는 탭 구분 머리글입니다.

`프로젝트 설정` A:I:

```text
키 별칭	담당자	모델	RPM 한도	RPD 한도	사용 여부	비고	초기 집계일	초기 사용량
```

`요청 기록` A:Q:

```text
요청 ID	사용자	프로젝트 별칭	키 별칭	모델	예약 시각(UTC)	마지막 갱신(UTC)	상태	입력 토큰	출력 토큰	합계 토큰	오류 코드	제한 종류	재시도 가능 시각(UTC)	집계일(KST)	후보 선택 전 요청 수	후보 선택 전 잔여량
```

`사용 현황` A:J:

```text
집계일(KST)	키 별칭	모델	요청 수	사용 중 수	추정 잔여량	상태	마지막 사용 시각(KST)	마지막 갱신(KST)	사용 중 사용자
```

배포 관리자는 코드의 `SHEET_ID`가 운영 중인 공용 시트를 가리키는지 확인하세요.
`POOL_TOKEN`, `GEMINI_SHARED_KEYS`, 시트 기록은 유지합니다.
그 뒤 코드 저장 → 배포 관리 → 기존 웹 앱 편집 → 새 버전으로 갱신합니다. 같은 배포 URL을 유지하면
연결된 클라이언트의 `.env` URL을 바꿀 필요가 없습니다. `SHEET_ID` 스크립트 속성을 따로 등록할 필요도 없습니다.
이 저장소의 코드 수정만으로 기존 웹 앱이 갱신되지는 않습니다.

```dotenv
GEMINI_POOL_MODE=sheets
GEMINI_POOL_URL=https://script.google.com/macros/s/배포ID/exec
GEMINI_POOL_TOKEN=스크립트속성과동일한비밀값
GEMINI_POOL_USER=사용자별칭
GEMINI_API_KEYS="{acct1:실제키1,
acct2:실제키2}"
GEMINI_API_KEY_OWNERS="{acct1:담당자1,
acct2:담당자2}"
GEMINI_MODELS=gemini-3.6-flash
```

## 장애 및 복구

- 예약 호출은 동일 요청 ID로 재전송합니다. 응답이 끝내 확인되지 않으면 분석하지 않습니다.
- 결과 기록 실패 시 `.pool_pending/`에 저장하고 다음 분석 전에 재전송합니다. 재전송도 실패하면 중단합니다.
- 프로세스 강제 종료/PC 전원 차단은 `finally`가 실행되지 않을 수 있습니다.
  서버는 마지막 heartbeat(없으면 예약 시각)로부터 10분이 지난 행을 사용중 잠금 집계에서 제외합니다.
  원래 기록과 요청 수는 유지됩니다. 네트워크 단절로 heartbeat만 멈춘 경우에도 잠금에서 제외될 수 있습니다.
  해당 PC의 분석이 확실히 종료됐는지 확인한 뒤 `요청 기록`에서 해당 요청의 H열 `사용중`을
  `결과 미확인`으로 변경하고 G열에 종료 시각(UTC)을 기록하세요. 요청 수는 그대로 유지됩니다.
  `후보 예약`만 남은 행은 해당 요청이 실행되지 않았음을 확인한 뒤 `선택 해제`로 변경하세요.
- 로그를 삭제하면 사용량이 줄어듭니다. 운영 중에는 기록 행을 지우지 마세요.
- 프로젝트가 이 시스템 밖에서 사용한 양은 자동 조회되지 않습니다. 공용 기록에 없는 사용량은 별도로 확인해야 합니다.
- 공용 집계는 Google의 실제 잔여 할당량 조회가 아닙니다. API 응답이 최종 기준입니다.

## 검증

아래 명령으로 분석기 환경에서 검증합니다. 외부 API 요청 없이 모의 시트와 클라이언트를 검증합니다.

```powershell
Set-Location .\analyzers  # 복제한 저장소 루트에서 시작
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p 'test*.py' -v
node --test tests/test_apps_script.cjs
```

공식 참고: https://developers.google.com/apps-script/guides/web
https://developers.google.com/apps-script/reference/lock/lock

분석기 설치 및 실제 `.env` 작성은 [Gemini 안내](../../README.md)를 참고하세요. `.env`, `.pool_pending/`와 분석 출력은 루트 `.gitignore`에서 제외합니다.

모델 전환 시 `Code.js`를 기존 웹 앱의 **새 버전으로 재배포**한 후 키 동기화 명령을 실행해야 합니다. 로컬 코드만 변경하면 이전 배포는 3.8/Antigravity를 계속 거부합니다. 활성 3.5/3.7 행이 있는 별칭은 기존 정책으로 중지됐던 3.8을 다시 사용으로 바꿉니다. 전환 완료 후 수동 중지한 3.8 행은 다음 동기화에서도 유지됩니다.

구형 모델 기록을 지우려면 먼저 세 시트를 백업한 뒤 편집기에서 `removeRetiredModelRecords`를 명시적으로 실행합니다. 3.5/3.7에 해당하는 설정·현황·요청 행만 제거하며, 최근 실행 중인 구형 예약이 있으면 중단합니다. 웹 요청과 키 동기화에서는 이 함수를 자동 실행하지 않습니다.

모델별 RPD는 사용자 설정 정책으로 Flash 3.6/3.8=20, Antigravity=100, Embedding 2=1000입니다. 동기화는 기존 행에도 RPD를 적용하되 RPM·수동 중지·기준 사용량·요청 이력을 유지합니다. 프로젝트 설정과 사용 현황은 Flash(acct1의 3.6/3.8부터 숫자순), 빈 행, Antigravity(acct1~20), 빈 행, Embedding(acct1~20)으로 표시합니다. 요청 기록은 시간순을 유지합니다.
