# Google Sheets 공용 키 풀

`reel_analyzer.py`는 기본적으로 공용 풀을 사용합니다. 아래 설정을 마치기 전에는
시트 연결 안내와 함께 중단합니다. 로컬 풀로 자동 우회하지 않습니다.

## 선택 순서

각 릴스 다운로드가 끝나고 Gemini 분석을 시작할 때마다 다음 과정을 반복합니다.

1. 로컬에 키가 있고 모델이 허용된 조합만 서버에 별칭으로 전달합니다.
2. 서버는 `프로젝트 설정`과 `요청 기록`을 읽고 사용중, 일일 소진, RPM 초과,
   일시 대기인 프로젝트/모델을 제외합니다.
3. 후보를 무작위로 최대 2개 뽑아 같은 ScriptLock 안에서 둘 다 `후보 예약`으로 기록합니다.
4. 당일 요청 **횟수**가 적어 잔여량이 많은 후보를 `사용중`으로 남기고 나머지는 `선택 해제`로 기록합니다.
   잔여량이 같으면 높은 Flash 모델을 사용합니다(3.8 → 3.7 → 3.6 → 3.5). 후보가 하나뿐이면 그 후보를 사용합니다.
5. Python이 선택된 키로 분석합니다. 실제 API 키/영상/분석 본문은 Apps Script에 보내지 않습니다.
6. 성공/실패/중단 시 결과를 기록하고 사용중 상태를 해제합니다. 429는 제한 종류도 기록합니다.
7. 다음 릴스와 API 오류 후 재시도 모두 새 요청 ID로 다시 추첨합니다.

모든 팀원이 **같은 Apps Script 배포**를 사용해야 잠금을 공유합니다.
프로젝트/모델이 같으면 키가 여러 개여도 같은 예약/사용량으로 취급합니다.
3.5/3.6/3.7/3.8 Flash만 허용하며 Flash Lite는 거부합니다.

## 시트 설정

기존 탭의 1~4행은 안내, 5행은 머리글, 6행부터 데이터입니다.

`프로젝트 설정`: A 프로젝트 별칭 / B 키 별칭 / C 담당자 / D 모델 / E RPM /
F RPD / G 사용 여부(`사용` 또는 `중지`) / H 비고 / I 초기 집계일 / J 초기 사용량.

- B열은 로컬 `.env`의 `GEMINI_API_KEY_LABELS`와 정확히 일치해야 합니다.
- 같은 프로젝트에 속한 키는 A열을 동일하게 입력합니다. 별칭만으로 프로젝트가 자동 식별되지는 않습니다.
- 한 프로젝트/모델의 한도 및 초기 사용량은 모든 별칭 행에 동일하게 입력합니다. 합산 시 중복 차감하지 않습니다.
- 사용자가 제공한 화면의 네 Flash 모델 한도는 RPM 5 / RPD 20입니다. 다른 팀원 프로젝트는 따로 확인해야 합니다.
- I/J열은 공용 기록 시작 **직전** AI Studio에 표시된 사용량을 초기값으로 넣는 선택 항목입니다.
  I열은 태평양시 날짜를 텍스트 `YYYY-MM-DD`로 입력합니다. 입력할 때 앞에 작은따옴표를 붙여도 됩니다.
  빈 초기값은 0으로 취급하므로 실제 외부 사용량이 있으면 직접 반영해야 합니다.
  운영 중 총사용량을 초기값으로 덮어쓰면 공용 기록과 이중 집계되므로 하지 마세요.

`요청 기록`: 기존 A:O 열 유지, P열에 `후보 선택 전 요청 수`, Q열에 `후보 선택 전 잔여량` 추가.
선택된 예약부터 요청 수를 1회 차감하며 미선택 후보는 차감하지 않습니다.
업로드 오류 등 실제 추론 전에 실패한 경우도 보수적으로 1회 집계합니다.
토큰 수는 성공 응답에 값이 있는 경우만 기록하며 토큰 잔여량을 보장하지 않습니다.

`사용 현황`은 서버 요청 시 갱신되는 조회용 표입니다. 이 탭을 수동 수정해도 예약/사용량은 바뀌지 않습니다.
일일 카운트는 태평양시 자정 기준, 진행 중 예약은 날짜가 바뀌어도 유지됩니다.

## Apps Script 설치/배포

1. 대상 Google Sheets의 확장 프로그램 → Apps Script를 엽니다.
2. `Code.js` 내용을 Apps Script의 `Code.gs`에 넣어 저장합니다.
3. 프로젝트 설정 → 스크립트 속성에 `POOL_TOKEN`을 추가합니다.
   32자 이상의 무작위 비밀값을 사용하고 로컬 `.env`의 `GEMINI_POOL_TOKEN`과 맞춥니다.
   키 원문이나 이 토큰을 시트 셀/코드/Git에 넣지 마세요.
4. 웹 앱으로 배포합니다. Python의 무인 호출 방식은 소유자 권한으로 실행하는 웹 앱을 사용하며,
   접근 가능한 엔드포인트에서 본문의 토큰을 검증합니다. 공개 접근 배포 및 Google 권한 동의는
   사용자가 해당 접근 범위를 확인하고 승인한 뒤 진행해야 합니다.
5. 배포된 `/exec` URL을 `.env`에 넣습니다. `/dev`는 사용하지 않습니다.
6. 모든 팀원이 동일한 배포 URL/토큰과 서로 구분되는 사용자 별칭을 사용합니다.
   코드 변경 시 웹 앱 배포 버전도 갱신해야 합니다.

```dotenv
GEMINI_POOL_MODE=sheets
GEMINI_POOL_URL=https://script.google.com/macros/s/배포ID/exec
GEMINI_POOL_TOKEN=스크립트속성과동일한비밀값
GEMINI_POOL_USER=사용자별칭
GEMINI_API_KEY_LABELS=acct1,acct2
GEMINI_API_KEYS=실제키1,실제키2
GEMINI_MODELS=gemini-3.5-flash,gemini-3.6-flash,gemini-3.7-flash,gemini-3.8-flash
```

## 장애 및 복구

- 예약 호출은 동일 요청 ID로 재전송합니다. 응답이 끝내 확인되지 않으면 분석하지 않습니다.
- 결과 기록 실패 시 `.pool_pending/`에 저장하고 다음 분석 전에 재전송합니다. 재전송도 실패하면 중단합니다.
- 프로세스 강제 종료/PC 전원 차단은 `finally`가 실행되지 않을 수 있습니다.
  이때 예약을 시간만 보고 자동 해제하면 살아 있는 분석과 충돌할 수 있으므로 자동 만료시키지 않습니다.
  해당 PC의 분석이 확실히 종료됐는지 확인한 뒤 `요청 기록`에서 해당 요청의 H열 `사용중`을
  `결과 미확인`으로 변경하고 G열에 종료 시각(UTC)을 기록하세요. 요청 수는 그대로 유지됩니다.
  `후보 예약`만 남은 행은 해당 요청이 실행되지 않았음을 확인한 뒤 `선택 해제`로 변경하세요.
- 로그를 삭제하면 사용량이 줄어듭니다. 운영 중에는 기록 행을 지우지 마세요.
- 프로젝트가 이 시스템 밖에서 사용한 양은 자동 조회되지 않습니다. 로컬 이전 기록도 자동 이관하지 않습니다.
- 공용 집계는 Google의 실제 잔여 할당량 조회가 아닙니다. API 응답이 최종 기준입니다.

## 검증

저장소 루트에서 실행합니다. 실제 Google/Gemini 호출 없이 모의 시트와 클라이언트를 검증합니다.

```powershell
cd analyzers/gemini
python -m unittest discover -s tests -p 'test*.py' -v
node --test tests/test_apps_script.cjs
```
