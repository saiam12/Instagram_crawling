# Collector Monitor (로컬 실행)

이 PC의 웹·Android 수집 상태, 실시간 데이터, 오류·종료 이력을 브라우저에서 확인합니다.
`127.0.0.1`에서만 접속할 수 있습니다. 기본 모니터링·시각화는 로컬에서 처리하며,
선택 기능인 영상 기획 추천은 생성 버튼을 누를 때 Gemini와 공용 시트 풀을 사용합니다.
수집 이력은 읽기 전용으로 조회하며, 실행 요청과 상태 기록은 수집 작업과 분리해 관리합니다.

## 실행

저장소 루트의 PowerShell에서:

```powershell
.\collectors\monitor\start.ps1
```

브라우저가 열리고 <http://127.0.0.1:8765>에서 확인할 수 있습니다.
기본 모니터는 수집기 가상환경인 `collectors/.venv`를 사용하며 추가 Python 패키지·Node.js 설치는 필요 없습니다.
Python 3.12 이상이 설치되어 있으면 가상환경과 필수 Python 패키지는 첫 실행에 자동으로 준비합니다.
모니터에서 Android 수집을 실행하려면 [Android 준비](../README.md#3-android-studio-설치-및-hybrid-준비)를 먼저 진행하세요.
Android 연결 패키지는 로컬 서버를 준비할 때 누락 시 자동 설치하며, Node.js·SDK·기기 로그인은 별도로 필요합니다.

```powershell
# 브라우저를 자동으로 열지 않기
.\collectors\monitor\start.ps1 -NoBrowser
# 다른 포트와 기존 데이터 폴더 사용 (collectors 기준)
.\collectors\monitor\start.ps1 -Port 8766 -DataDir data/collector
# 모니터만 종료: 수집기와 Android 워커는 계속 실행
.\collectors\monitor\stop.ps1
```

여러 포트로 실행하면 `stop.ps1`은 가장 최근에 실행한 모니터만 종료합니다.
모니터를 터미널에서 직접 실행하려면 `collectors/monitor`에서
`..\.venv\Scripts\python.exe -B backend/server.py --port 8765`를 사용하고 Ctrl+C로 종료하세요.
PowerShell 실행이 차단되면 현재 터미널에서 `Set-ExecutionPolicy -Scope Process Bypass` 후 다시 실행합니다.

## 표시하는 정보

Android 작업자가 실행 중이면 모니터가 읽기 전용 진단 기록기의 생존 여부를 60초마다 확인하고, 종료된 기록기를 다시 실행합니다. 기록기는 에뮬레이터를 재부팅하거나 터치하지 않습니다. 상태와 실제 기록 경로는 `collectors/runtime/diagnostics/android-watch/current.json` 및 해당 세션의 `status.json`에서 확인할 수 있습니다. `collectors/scripts/diagnostics/watch-android-diagnostics.ps1 -Stop`으로 명시적으로 중지한 상태는 자동으로 해제하지 않습니다. 모니터를 닫으면 기록기 자동 감시도 끝나지만 이미 실행된 기록기는 별도로 계속 동작합니다.

- **릴스 구분 선택:** 수집 현황 상단과 실시간 데이터의 `릴스 구분`에서 전체·한국·외국·미확인 (-)을 선택합니다. 저장 기록 수, 최근 1시간, 회차별 기록과 활동 그래프·목록이 선택에 따라 바뀝니다. 회차·검색·Android 값 필터도 함께 적용할 수 있습니다. 대기열·실행 시간·프로세스 상태·최근 성공 시각·워커 처리 누계는 전체 기준입니다. Android 활동 그래프는 최근 로그의 릴스 URL을 현재 최신 분류에 연결해 집계합니다.
- **분류 기준:** 한국은 `korean=true`, 확인된 외국은 `korean=false`, 미확인은 `-`로 표시하며 전체·한국·외국·미확인 필터를 제공합니다. 국가·수동 판정 근거가 없는 분류는 미확인으로 표시합니다. 실시간 데이터 제목을 눌러 상세의 릴스 구분을 선택하고 **구분 저장**을 누르면 같은 릴스의 모든 회차에 적용됩니다. 수동 선택은 데이터셋 `.collector/korean_overrides.json`에 저장되며 재수집 후에도 우선합니다. 수집·분석 시각화에도 같은 필터가 있으며 최신 분류는 원본 재선택·최신 분석 불러오기로 갱신합니다. 파일 시각화의 최신 집계는 회차 안에서 최신 기록을 고른 뒤 구분을 적용합니다.

- **웹·Android 별도 상태:** 프로세스, 최근 응답, 마지막 수집 성공, 연결/화면 복구 상태.
- **동작 시간:** 설정 실행 시간, 시작 후 경과, 종료 예정까지 남은 시간. 경과에는 대기·재시도가 포함됩니다.
- **활동 그래프:** 시계 기준 고정 5분 구간(예: 18:00~18:05)의 처리 건수. 마지막 구간은 집계 중이며, 웹 Y축은 40건, Android는 70건까지 표시합니다. Android는 최근 로그 범위 기준입니다.
- **재수집 대기:** 스케줄러의 최근 집계 기준으로 재수집 예정 시각이 지났지만 다음 수집 기록이 아직 저장되지 않은 릴스 수. 아직 예정 시각이 오지 않은 항목은 제외하며, 진행 중인 미저장 항목은 포함될 수 있습니다. 숫자에 마우스를 올리면 집계 시각을 확인할 수 있고, 집계 정보가 없으면 `—`로 표시합니다.
- **실시간 수집량:** 재수집 포함 기록 수, 최근 1시간 저장 기록 수.
- **Android 큐:** 대기·처리 중·결과 반영 대기 건수. 현재 워커 처리 수는 해당 워커 실행 이후의 값입니다.
- **데이터:** 최신 수집순 검색·필터·페이지 이동, 제목을 눌러 전체 값과 Instagram 링크 확인.
- **데이터 시각화:** 왼쪽 메뉴에서 별도 페이지를 열고 CSV·JSON·XLSX 파일을 선택하면 회차별 건수, 시간대별 수집량, 지표 분포·상위 릴스와 평균·중앙값·수집률을 표시합니다.
- **CSV 읽기:** 캡션 안의 이중 따옴표 이스케이프를 처리하며 헤더보다 값이 많은 행은 오류로 안내합니다. 저장된 캐시 대신 원본 파일을 다시 선택하면 파일 내용을 새로 읽습니다.
- **상태 이력:** 수집 로그의 발생 시각과 모니터가 감지한 상태 변경 시각을 구분합니다.

상태와 이력은 3초마다 파일을 읽습니다. 데이터 표만 갱신을 일시정지해 값을 살펴볼 수 있습니다.
기본 `collector/.datasets/`와 해당 모니터가 시작한 저장 폴더를 관찰합니다.
CSV 이력, 저장 대기 journal, 아직 반영되지 않은 Android 완료 결과를 읽으며 수집기 파일은 수정하지 않습니다.
엑셀을 열거나 잠그지 않습니다. 누락 값은 `—`, 실제 0은 `0`, 비공개 값은 `비공개`로 구분합니다.

## 파일 데이터 시각화

왼쪽 **데이터 시각화** 메뉴 또는 <http://127.0.0.1:8765/visualize.html>을 엽니다.
**파일 선택**으로 한 파일을 열거나 파일 선택 영역에 끌어 놓으세요.

- 지원: UTF-8/CP949 CSV, 기록 배열 JSON(또는 `items`/`records`/`rows`/`reels`/`data` 배열), XLSX. `.xls`는 XLSX로 저장해야 합니다.
- 예: `reels.csv`, `reels.xlsx`, `.collector/reels_history_active.csv`. 수집 파일의 기본 컬럼과 조회수·좋아요·수집 시각 등 일반적인 한글 컬럼명을 인식합니다.
- XLSX는 읽을 수 있는 시트를 선택할 수 있으며, `2nd collect_...`와 같은 회차별 가로 컬럼은 개별 수집 기록으로 펼칩니다. 수집 기록을 찾지 못한 시트는 이유와 함께 제외합니다.
- 회차·시트·지표를 선택하고 **릴스별 최신 기록 / 모든 수집 기록**을 전환할 수 있습니다. 회차별·시간대별 그래프는 회차 필터를 적용한 모든 기록을, 평균·중앙값·분포·상위 릴스는 선택한 지표 집계 기준의 기록을 사용합니다.
- 조회수·좋아요·댓글·공유·재게시·저장·팔로워를 비교합니다. 누락·비공개·unavailable과 인식 불가능한 숫자는 평균·중앙값에서 제외하고 실제 0은 포함합니다. `123(+10)` 형식은 앞의 값 123을 사용합니다. K/M·만 등 축약 숫자를 임의의 정확한 값으로 바꾸지 않습니다.
- **그래프 크기:** `한 행의 그래프 수`에서 2개·3개·4개를 선택하면 가로 폭을 화면에 맞춥니다. 그래프 오른쪽 가장자리의 선을 좌우로 끌면 전체 너비가, 하단의 선을 위아래로 끌면 전체 높이가 바뀝니다. 모든 그래프와 그래프 추가 박스에 같은 크기를 적용하며, 직접 정한 너비에 맞춰 열 수를 자동 배치합니다. 손잡이에 포커스를 두고 방향키로도 조절합니다. 두 번 클릭하면 해당 방향의 기본 크기로 돌아갑니다. 공통 크기는 작업에 저장되고 좁은 화면에서는 열 수가 자동으로 줄어듭니다.
- 시간은 한국 시간으로 표시합니다. 시간대 표시가 없는 날짜와 수집기 XLSX 날짜 일련번호는 한국 시간으로 해석합니다. 시각을 읽지 못한 기록은 시간 그래프에서 제외하고 제외 건수를 표시합니다. 긴 기간은 자동으로 넓은 시간 구간으로 합쳐 표시합니다.
- 한 파일 최대 20 MiB, 전체 정규화 기록 100,000건, 256개 컬럼, XLSX 20개 시트·압축 해제 64 MiB를 지원합니다. 큰 파일은 필요한 시트나 기간만 CSV로 나눠 선택하세요.
- 파일은 기존 localhost 인증 검사를 통과한 뒤 이 PC 서버의 요청 메모리에서만 읽습니다. 수집 파일·폴더를 변경하거나 업로드 파일을 저장하지 않으며 외부 서비스 요청도 하지 않습니다. 여러 파일을 동시에 처리하지 않습니다.
- **읽기 취소**와 **파일 닫기**를 지원합니다. 다른 파일 읽기에 실패하면 이전 결과를 유지합니다. 자동으로 원본 파일 변경을 감시하지 않으므로 최신 파일은 다시 선택하세요.
- **이전 작업 자동 복원:** 마지막으로 읽은 파일의 정규화된 데이터, 시트·회차·집계 기준·지표·시간 간격을 브라우저 IndexedDB에 저장합니다. 다른 메뉴로 이동하거나 새로고침한 뒤 돌아오면 마지막 저장 작업을 복원합니다. 원본 파일과 서버의 수집 폴더에는 쓰지 않습니다.
- **파일 닫기**는 현재 그래프만 닫으며 저장 작업을 유지합니다. **저장된 작업 삭제**는 이 브라우저의 시각화 캐시를 삭제하고 현재 그래프를 닫습니다. 원본 수집 파일은 삭제하지 않습니다.
- 캐시는 같은 브라우저와 같은 주소(호스트·포트)에서 사용합니다. 브라우저 데이터 삭제, 비공개 모드, 저장 공간 부족 등으로 캐시가 없어지거나 저장이 거절될 수 있습니다. 저장·복원 실패는 화면에 표시하며 파일 분석 기능은 계속 사용할 수 있습니다. 여러 작업 이력 대신 마지막 작업 한 개를 보관합니다.

## 명령어 안내

**명령어 안내**에서 PowerShell 실행 예시와 수집 시간·재수집 횟수·저장 폴더·기기 선택 옵션을 확인하고 복사할 수 있습니다. 프로젝트의 `collectors` 폴더에서 명령어를 실행하세요. 기본 수집 모드는 웹 + Android이며, `--collector-mode web`을 추가하면 웹만 수집합니다. `--background`를 빼면 창을 표시합니다.

터미널에서 시작한 수집은 `Ctrl+C`로 중지합니다. 현재 저장을 마무리하며 대기열과 저장 데이터는 유지됩니다. 같은 브라우저 로그인 프로필로 중복 실행하지 마세요.

**실행 설정 및 작업**에서 종류·모드·시간·횟수·저장 폴더·기기를 지정합니다. 명령어 미리보기를 확인한 뒤 **수집 시작**을 누르면 확인창을 거쳐 백그라운드로 실행합니다. **Android 준비**로 연결 기기나 에뮬레이터를 준비할 수 있습니다. 아래 **실행 작업**에서 로그를 열거나 해당 작업을 중지합니다. 터미널에서 시작한 작업은 상단 현황에서 관찰하며 해당 터미널에서 중지합니다. 실행 중인 수집기가 감지되면 중복 시작을 차단합니다.

**첫 로그인은** `collectors`에서 `./collector.ps1 --collector-mode web --max-items 50`처럼
브라우저 창을 표시해 완료하세요. 웹과 Android 로그인은 별개입니다.
기기 serial이 바뀌면 기존 워커가 자동으로 새 기기로 바뀐다고 보장하지 않습니다. 기기 선택과 실행 로그를 확인하세요.

## 이력과 판단의 한계

- 프로세스가 살아 있는 것과 새 데이터가 저장되는 것을 따로 표시합니다.
- 웹 오류보다 나중에 실제 저장 성공이 확인되면 해당 경고를 해제합니다. 새 배치 시작이나 응답 갱신만으로 오류를 숨기지 않습니다. 구버전 예약 관리자가 같은 오류를 계속 다시 게시하더라도, 같은 실행·오류·누적 실패 횟수의 경고는 복구 후 다시 켜지지 않습니다. 실패 횟수가 늘거나 오류가 바뀌면 새 오류로 표시합니다. 모니터 재시작 시 복구 관찰 상태는 새로 시작하므로, 오래된 오류가 남은 구버전 수집기는 다음 실제 저장을 확인할 때까지 경고가 잠시 보일 수 있습니다. 새 수집기 소스는 정상 배치 완료 시 현재 오류를 비우며, 누적 실패 횟수와 원본 로그는 유지합니다.
- 응답이 3분 이상 없으면 `진행 확인`으로 표시합니다. 정상적인 긴 대기와 고장을 자동으로 단정하지 않습니다.
- 상태 파일의 PID와 실제 프로세스 생성 시각을 비교해 PID 재사용을 구분합니다. 접근 권한이 없으면 확인 불가로 표시합니다.
- 강제 종료는 정확한 종료 시각 대신 **처음 종료를 감지한 시각**을 기록합니다. 모니터가 꺼져 있던 동안의 감지는 할 수 없습니다.
- 과거 이력은 남아 있는 로그 범위까지만 표시합니다. 시작·중지 이력은 원본 로그에서도 읽고,
  상세 오류와 Android 활동 막대는 최근 256KB 로그를 사용합니다. 화면에는 최근 이력 100개를 표시합니다.
- 읽는 도중 파일이 교체되거나 잠기면 직전 데이터를 유지합니다. 수집기 상태 갱신과 공개 출력 반영 시점은 다를 수 있습니다.
- 모니터·PC가 꺼지면 웹 화면에 연결 끊김을 표시합니다. PC가 꺼진 동안 수집을 계속하거나 외부 알림을 보내지는 않습니다.

`runtime/`에는 모니터 감지 이력(`events.jsonl`), 실행별 옵션·로그·종료 코드(`runs/`), 서버 PID와 로그가 저장됩니다.
이 폴더는 Git에서 제외됩니다. 실제 데이터와 로그인 프로필은 복사하거나 외부로 보내지 않습니다.
임의 셸 명령 입력은 제공하지 않으며, 정해진 옵션만 전달하고 변경 요청은 같은 화면에서만 받습니다.

회차별 수집 릴스 패널은 선택 데이터셋의 저장 기록을 collection_number별로 집계하고 3초마다 갱신합니다. 새 회차는 자동 추가하며 회차 없는 기록은 미지정으로 표시합니다. Android 보강 완료 건수와는 별개입니다.

Android `unreadable`·화면 읽기 재시도·워커 지연/종료·단순 ADB 조회 시간 초과는
상태 문구로 표시하며 패널을 깜빡이게 하지 않습니다. 웹+Android 실행 중에는
10초 간격의 읽기 전용 ADB 확인으로 기기 부재/offline/접근 불가, 입력 디스패처
중단, 현재 입력 대상의 앱 응답 없음/오류 창을 확인합니다. 같은 기기의 같은
문제가 두 번 연속 확인될 때만 빨간색 패널 깜빡임을 켜고 정상 확인 시 해제합니다.
웹 전용·일시정지·명시적 수집 중지는 알림에서 제외합니다. 터치 명령·앱 재시작·
에뮬레이터 재부팅은 보내지 않습니다. 이 검사는 모든 앱 터치가 성공한다는
보장은 아니며, 입력 서비스로 확인하지 못한 문제는 경고 문구만 표시합니다.

## 영상 기획 추천 (RAG 초안)

왼쪽 메뉴는 **수집 관리**(수집 현황·실시간 데이터·상태 이력·실행 설정)와
**데이터 활용**(수집 시각화·분석 시각화·영상 기획 추천)으로 구분합니다.
모든 페이지가 같은 순서와 정렬을 사용합니다.

### 분석 데이터 시각화

**분석 시각화**(`/analysis.html`)는 `collectors/data/collector/reel_analysis.json`을
읽어 콘텐츠 유형·추천 타겟 연령/성별·Hook 강도·소구 유형·장면 기준 길이를
집계합니다. 차트 막대를 누르면 해당 분류의 릴스를 볼 수 있으며, 내용 검색과
유형·성별 필터, 20건씩 페이지 이동, 분석 근거 상세창을 제공합니다.
타겟은 AI의 추천이며 실제 시청자 통계가 아닙니다. 복수 타겟·소구점은 릴스당
분류별 1회 집계하므로 전체 비율의 합이 100%를 넘을 수 있습니다.
길이는 전체 분석 장면의 마지막 종료 시각 기준 근사값입니다. 상세창의 장면
본문은 최대 100개이며 건수/길이 계산은 전체 장면을 사용합니다.

분류 차트 아래 **분석 릴스 지표 비교**에는 팔로워 기준 6개·조회수 기준 6개와 영상 길이/조회수·좋아요
그래프가 있습니다. X·Y축을 골라 그래프를 계속 추가하고, 축 교환·순서 이동·삭제를 할 수 있습니다.
한 행에 2·3·4개를 선택하거나 가로·세로 손잡이로 모든 그래프 크기를 함께 조절합니다.
그래프 추가 박스는 항상 마지막이며 동일한 크기입니다. 배치·축·크기는 분석 페이지의 캐시에 저장됩니다.
내용·유형·타겟·한국/외국·차트 분류 선택을 모든 그래프에 함께 적용하며, 현재 선택한 릴스의 유효한
지표를 모두 표시합니다. 수집된 영상 길이를 우선하고 없으면 장면 기준 근사값을 사용합니다.

파일은 32 MiB·10,000건 이하 JSON 배열을 지원합니다. 잘못된 레코드와 중복의
제외 건수를 표시하며 같은 릴스 ID는 파일 뒤쪽 레코드를 우선합니다. 원본은
변경하지 않습니다. 분석 스냅샷과 필터는 브라우저 캐시에 자동 저장하고,
재방문에는 캐시를 복원합니다. **최신 분석 불러오기**로 파일 내용을 갱신하며
오류가 생겨도 이전 화면은 유지합니다. 이 화면은 새 Gemini 요청을 보내지 않습니다.

### 기획안 입력과 검색

왼쪽 **영상 기획 추천** 탭에서 분석 파일과 제품·타겟·목적을 확인·입력합니다.
핵심 소구점(강조할 장점)과 제작 조건(예: 얼굴 노출 없이 실내 촬영)은 각각
200자 이내의 **선택 입력**입니다. 비워 두어도 검색·생성이 가능합니다.
소구점은 사례 검색과 기획에 반영하고, 제작 조건은 촬영 구성에 반영합니다.
영상 형식은 사례와 조건에 맞게 제안합니다. 입력한 제품 효능을 검증된 사실로
단정하거나 새로운 효능을 임의 추가하도록 요청하지 않습니다.
**유사 사례 찾기** 전에 **참고 사례 구분**에서 전체·한국·외국·미확인을 선택할 수 있습니다.
저장된 분류와 수동 수정값을 적용하며 미확인은 외국으로 취급하지 않습니다.
선택한 범위에서 지정된 Analyzer JSON의 분석문과 입력 조건을 `gemini-embedding-2`로
768차원 임베딩한 뒤 코사인 유사도와 로컬 BM25 순위를 RRF(k=60)로 결합합니다.
**내 계정 팔로워 수**를 입력하면 내용 검색 상위 30개 후보를 대상으로 내용 검색 점수 70%와
팔로워 규모 점수 30%를 합쳐 추천합니다. 규모 점수는 `1 / (1 + abs(log2((사례 팔로워+1)/(입력 팔로워+1))))`이며
팔로워 미수집 사례에는 규모 가산점을 주지 않습니다. 입력하지 않으면 기존 내용 중심 순위를 유지합니다.
참고 지표는 Collector·Fashion·Refresh의 수집 파일을 릴스 ID로 연결하고, JSON에 없는 릴스는 XLSX에서도
찾습니다. 작성자의 더 최근 팔로워 수가 users.json에 있으면 함께 반영합니다. 수집 시점과 출처를 보관하며
분석 원본은 수정하지 않습니다. 실제 수치만 Antigravity에 전달하고 비공개·미수집 항목은 수치에서 제외합니다.
화면은 통합 순위·코사인 유사도·단어 점수를 구분합니다. 유사도는 성과 확률이 아닙니다.
BM25는 한국어 bigram 및 제한된 동의어 확장을 사용합니다. 최대 5,000개 릴스를 사용합니다.
분석문과 검색 조건은 Google API로 전송되며 영상 원본은 전송하지 않습니다.
모델·차원·입력문별 벡터는 `analyzers/output/reel_embeddings.sqlite3`에 캐시되어,
변경된 분석문과 새 검색어만 다시 요청합니다. 첫 검색은 준비 시간이 필요합니다.
새 입력은 최대 8개씩 순차 전송하며, 긴 입력은 더 작은 묶음으로 처리합니다.
로컬의 보수적인 최근 60초 전송량 기준에 도달하면 잠시 대기합니다. 정확한 TPM 계측값은
아니며, 다른 프로그램의 프로젝트 사용량까지 합산하지는 않습니다. 완료된 묶음은 즉시
캐시하므로 다음 검색에서 재사용합니다. 초기 색인의 대기 한도는 최대 1시간입니다.
API·공용 키 풀·캐시에 문제가 생기면 경고와 함께 기존 BM25 검색을 제공합니다.
조건과 맞지 않는 자료만 검색되는 경우 입력을 바꾸거나 해당 분야 데이터를 먼저 확보하세요.

참고 자료는 **`collectors/data/collector/reel_analysis.json` 한 파일**입니다.
유효한 분석이 있는 릴스만 검색하며, 미분석 수집 기록이나 다른 Analyzer 출력은 합치지
않습니다. 파일이 없거나 JSON 형식이 잘못되면 오류를 표시합니다. 원본 파일은 수정하지
않습니다. 참고 사례별 펼침 영역에서 전송할 내용을 확인할 수 있습니다. 자료 경로가
달라진 이전 캐시는 스냅샷으로 남지만 새 검색 전에는 생성에 사용할 수 없습니다.

### Gemini 준비

저장소 루트 PowerShell에서 Analyzer 환경을 준비합니다(이미 설치됐다면 재설치 불필요).

```powershell
python -m venv analyzers/.venv
.\analyzers\.venv\Scripts\python.exe -m pip install -r analyzers/requirements.txt
```

`analyzers/.env.example`을 참고해 `.env`를 설정합니다. 기존 `.env`는 덮어쓰지 마세요.
추천 기능은 기존 `pool.SheetsKeyPool`을 직접 사용하며 로컬 키 풀로 자동 전환하지 않습니다.
`GEMINI_POOL_MODE=sheets`, `GEMINI_POOL_URL`, `GEMINI_POOL_TOKEN`, `GEMINI_POOL_USER`,
동기화된 `GEMINI_API_KEYS`, 시트 풀이 허용하는 `GEMINI_MODELS`가 필요합니다.
키 동기화/Apps Script 배포는 [기존 시트 풀 안내](../../analyzers/pool/apps_script/README.md)를 따릅니다.

분석 모델은 `gemini-3.6-flash`이며, 모니터의 생성 버튼은 Flash 기획 단계를 거치지 않고 Antigravity에 가이드 영상과 영상별 장면 구성·대본을 직접 요청합니다. 1~3번은 각각 상위 참고 사례의 형식, 4~6번은 서로 다른 사례의 특징을 혼합합니다. 입력 조건·참고 분석·전체 `scene_details`를 함께 전달하며 키 예약 후 Antigravity 요청 6개를 병렬 전송합니다. 검증된 장면 설계는 Pillow/FFmpeg로 MP4(540×960, 10fps, 테스트 길이 5~30초)로 변환합니다. 각 영상 카드에서 장면별 시간·구도·카메라·동작·대본·화면 자막·근거 장면을 확인합니다. 대본은 텍스트이며 음성 합성은 하지 않습니다. 일부 실패해도 완료된 영상과 대본은 보존하고 자동 재전송하지 않습니다. `.env`의 `GEMINI_GUIDE_ENABLED=false`는 영상·대본 생성을 비활성화합니다.
화면의 '설정 확인'은 로컬 설정을 읽었다는 뜻이며 실제 연결·잔여 한도를 검증한 뜻이 아닙니다.
키나 풀 토큰은 브라우저에 입력하지 않으며 응답/화면/로그에 노출하지 않습니다.

사례와 전송 안내를 확인한 뒤 **가이드 영상·대본 생성**을 누르면 입력 조건 및
최대 6개 사례의 분석·장면 상세·수집 지표가 Google Antigravity로 전송됩니다. 원본 영상 파일은
다운로드하거나 보내지 않으며 Instagram에 새 요청도 하지 않습니다. 별도 Analyzer
프로세스에서 기존 풀 예약·heartbeat·사용량 정산을 수행합니다. 동시 기획 작업은 1건이고, 그 안에서 가이드 요청 6개는 병렬로 실행하며
요청 ID로 중복 접수를 막습니다. 각 영상은 한 번 요청하며,
시간 초과/응답 유실/5xx 오류는 자동으로 생성 요청을 다시 보내지 않습니다.

각 영상의 제목, 길이, 참고 사례와 특징, 3~8개 장면의 시간·촬영 구도·카메라·동작·대본·자막을
표시합니다. 알 수 없는 근거 ID나 잘못된 JSON은 성공 처리하지 않습니다. 기존 캐시의 공통 기획안도 계속 읽을 수 있습니다.
가이드는 실사 생성 영상이 아닌 촬영 동작 도식입니다. 인물의 옷깃·지퍼·주머니 윤곽과
팔·손 관절 동작을 그리며, 장면 사이 짧은 전환을 적용합니다. 새 설계는 인물별 `gesture`를
지정하고, 이전 저장 설계는 지원되는 동작 설명을 매핑하여 API 재호출 없이 다시 렌더링할 수 있습니다.
검색 점수는 성과 예측이 아니며 예상 바이럴 점수를 임의 생성하지 않습니다.

추천 길이는 초기 기획 범위인 5~180초의 정수로 제안합니다(플랫폼의 업로드 제한을
뜻하지 않습니다). 분석 파일에 있는 참고 사례의 `video_duration_seconds` 값을 전달하고, 없을 때는
Analyzer `scene_details.end_second` 최댓값을 분석 장면 기준 근사값으로 구분합니다.
자료에 길이가 없으면 추정임을 명시합니다. 장면별 시작/종료는 정수 초이며 0부터
빈 구간/겹침 없이 이어지고 마지막 종료가 추천 길이와 같아야 합니다. 이 조건을
벗어난 응답은 성공 처리하지 않습니다. 기획안에는 추천 길이와 장면별 시작·종료 시각을 함께 표시합니다.

마지막 입력·참고 사례·생성 기획안·진행 작업 ID는 브라우저 IndexedDB에 한 작업으로
자동 저장합니다. 시각화와 같은 `workspace-cache.js` 저장 로직을 사용하지만 DB는
별개입니다. 새로고침/탭 이동/서버 재시작 후에도 저장된 결과는 복원됩니다. 키·풀
토큰은 저장하지 않습니다. 저장된 결과는 당시 자료의 스냅샷이며, 생성하려면 사례를
다시 검색해야 합니다. 전송 동의는 복원하지 않고 Gemini 호출도 자동으로 재실행하지
않습니다. 입력 변경 후 남은 이전 기획안은 당시 조건과 원래 근거를 계속 표시합니다.
저장된 작업은 당시 입력 조건과 결과를 확인하는 데 사용합니다.
**저장된 작업 삭제**의 확인창에서 해당 브라우저의 작업을 지울 수 있으며 원본
수집/분석 파일은 유지됩니다. 브라우저 저장 공간·시크릿 모드·사이트 데이터 삭제에
따라 저장이 실패하거나 제거될 수 있으며, 실패 시 현재 결과는 유지합니다.

서버의 검색/생성 작업도 메모리에 최대 20건씩 보관하며 새 작업 접수 시 1시간 초과
항목을 정리합니다. 이 서버 상태는 재시작 시 소실되지만 브라우저에 저장된 결과는
남습니다. 서버 재시작/통신 장애 시 아직 완료되지 않은 API의 처리 여부는 불확실할
수 있으므로 한도를 확인한 뒤 사용자가 재요청해야 합니다. 진행 ID는 sessionStorage에도
보관하고, 생성 요청을 보내기 전에 IndexedDB 저장 완료를 기다립니다.

### 모델 실행과 운영

서버 코드와 설정은 모니터 서버를 시작할 때 읽습니다. `start.ps1`만 다시 실행하면
기존 서버를 재사용하므로, 적용할 때는 `stop.ps1` → `start.ps1` 순서로 실행하세요.
이 명령은 수집기와 Android 워커를 중지하지 않습니다. 수집기 Python 소스 변경은 별개입니다.

`recommendations.py`의 `worker()`가 모델 호출 경계입니다. 로컬 AI를 연결할 때는
같은 `{brief, references}` JSON 입력과 `{plan, provider, model}` 출력/검증 계약을
따르는 어댑터로 교체하면 화면과 로컬 검색은 유지할 수 있습니다. 현재 로컬 AI 호출은
구현하지 않았습니다. [설계 및 작업 범위](docs/RECOMMENDATION.md)를 참고하세요.

SDK 참고: [Google Gen AI Python SDK](https://github.com/googleapis/python-genai).


신규 저장 목표 개수와 탐색 구간별 저장 상한은 없습니다. 신규 탐색 시간과 전체 실행 시간 내에서 수집을 이어갑니다.

## Refresh 탭

상단의 **수집기 / Refresh** 탭으로 데이터를 분리해서 봅니다. Refresh에서는 회차별 기록, 지표, Android 대기열과 상태 이력을 확인합니다. 입력함 기록이 있으면 등록 대기·등록 이력·수집 종료 요청·마지막 측정 용량·예약량도 표시합니다. 등록 이력은 완료 건수가 아닙니다.

`collectors/data/refresh`와 입력함을 사용하는 데이터 영역을 자동 탐색합니다. 입력함 기록이 없는 항목은 관련 수치를 `—`로 표시합니다. 신규 수집과 재수집의 조회·이벤트·실행 설정은 각 탭에서 구분합니다.

바로 열기: <http://127.0.0.1:8765/?source=refresh#overview>

## 모니터링 동작

서버는 수집 이력·예약·Android 큐를 읽어 화면에 제공하고, 사용자가 요청한 실행 작업을 관리합니다. 브라우저는 조회·필터·시각화와 작업 상태 확인을 담당합니다. 화면 데이터와 실행 기록은 별도 영역에 저장하므로 모니터 종료가 수집기 종료를 뜻하지 않습니다.

| 기능 | 처리 범위 |
|---|---|
| 상태 조회 | 수집량·회차·실행 시간·웹/Android 상태와 오류 이력을 표시합니다. |
| 데이터 시각화 | 저장된 데이터와 직접 선택한 파일을 필터링하고 지표를 비교합니다. |
| 작업 제어 | 실행 조건을 검증한 뒤 수집·기기 준비 작업을 요청합니다. |
| 기획 추천 | 관찰 근거를 검색하고 사용자가 요청할 때만 모델로 기획안을 생성합니다. |

실행·종료는 `start.ps1`, `stop.ps1`을 사용합니다. 직접 서버를 실행할 때는 `backend/server.py`를 지정합니다. 운영 기록은 `../runtime/monitor/`에 저장합니다. 시각적 기준과 상호작용 원칙은 [디자인 기준](docs/DESIGN.md)과 [동작 계약](docs/UX-CONTRACT.md)을 참고하세요.

촬영 가이드는 기획안의 장면 구성 아래 PNG로 표시하며 **이미지 저장**으로 내려받습니다. 생성 PNG와 검증 전 응답은 `analyzers/output/guides/`에 실행별 파일로 보관합니다. 토큰 한도로 실행이 중단돼도 검증 가능한 이미지가 있으면 표시하고 누락 가능성 안내를 함께 보여줍니다. 기존 캐시에는 새 이미지를 임의로 붙이지 않으므로 새 기획안을 생성해야 합니다.

가이드 이미지는 원래 제목·크기·배치를 유지합니다. 기본적으로 접혀 있으며 **가이드 이미지 펼치기/접기**로 열고 닫습니다. 펼치기·접기는 API를 호출하지 않습니다. PNG와 렌더링 버전·원본 해시를 서버에 캐시하고 브라우저 작업 캐시에도 이미지를 저장합니다. 새로고침·모니터 재시작 시 저장된 이미지를 복원하며, 기존 이미지의 레이아웃 갱신도 저장 응답으로 처리해 Gemini·Antigravity를 다시 호출하지 않습니다.

가이드 MP4·장면 설계·API 응답은 `analyzers/output/guides`에 저장됩니다. 웹에는 참고 형식 3개/혼합 3개를 나눠 재생·다운로드 링크와 출처·반영 특징을 표시합니다. 브라우저는 결과 메타데이터를 캐시하고 영상은 로컬 서버에서 범위 요청으로 읽습니다. 새로고침·펼치기·재생 시 API를 재호출하지 않습니다. 예전 PNG 가이드는 기존 캐시로 계속 열 수 있습니다.
