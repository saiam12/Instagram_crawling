# 영상 기획 추천 — 구현 범위

제품·타겟·목적을 입력하고, 핵심 소구점·제작 조건은 선택으로 입력한다. 지정된
`collectors/data/collector/reel_analysis.json`의 분석 레코드만 참고한다.
미분석 수집 기록과 다른 Analyzer 출력은 합치지 않는다. 로컬 BM25 검색(한국어 글자 bigram 포함)으로
상위 6개 사례를 고른다. 임베딩이나 예측 모델을 학습한 시스템은 아니다.

화면은 기존 테마와 메뉴를 사용한다. 넓은 화면에서 입력/참고 사례를 왼쪽,
기획안을 오른쪽에 배치하고 작은 화면에서는 세로로 배치한다. 참고 사례를
먼저 확인한 다음 명시적으로 Gemini 전송 버튼을 누른다. 외부로 보내는 것은
입력 조건과 표시된 사례의 텍스트·수집 지표뿐이며 영상 파일은 보내지 않는다.

`recommendations.py`는 자료 연결·검색·작업 상태를 담당한다.
`gemini_recommend.py`는 Analyzer Python 환경에서 기존 SheetsKeyPool을 사용한다.
이 프로세스 경계의 JSON 입출력을 향후 로컬 모델 어댑터로 교체할 수 있다.
키와 풀 토큰은 서버 프로세스에서만 읽고 브라우저에 제공하지 않는다.
Instagram 접속, 수집기 재시작, 기존 데이터 수정은 이 기능의 동작이 아니다.

## 구현 순서

1. 입력 검증, 자료 연결, 검색 결과와 근거 식별자 구현.
2. 기존 시트 풀 예약/정산과 JSON 응답 검증을 사용하는 Gemini 어댑터 구현.
3. 비동기 작업 API와 중복 요청 방지, 동일 메뉴의 추천 화면 연결.
4. 문법 검사·소스 검토 및 로컬 화면 관찰. 자동 테스트/실제 Gemini 요청은
   별도 요청 없이 실행하지 않는다. 예시 결과를 실제 API 결과로 표시하지 않는다.

## 한계

검색 점수는 텍스트의 유사도 순위이며 성공 확률이 아니다. 데이터에 없는
제품/타겟은 일치도가 낮을 수 있다. Analyzer 분석도 관찰과 추론의 한계가
있다. 기획안에 근거 사례 및 한계를 함께 표시하고 가상의 바이럴 점수를
만들지 않는다. 마지막 입력·참고 사례·생성 기획안·진행 작업 ID를 같은
브라우저의 IndexedDB에 보관한다. 키나 풀 토큰은 저장하지 않는다.

## 초기 구현 확인 (자료 경로 변경 전)

Python/JavaScript 문법 검사와 별도 소스 검토를 수행했다. 로컬 미리보기에서
검색 가능한 릴스 2,459개(Analyzer 분석 122개)를 연결하고, 예시 입력으로
실제 참고 사례 6개를 찾는 것을 관찰했다. 5,000개 제한에 도달한 자료는
아니었다. 수집 기록이 변하면 이 수치는 달라진다.

Analyzer 환경의 로컬 설정 확인은 성공했지만 실제 Gemini API 생성,
시트 예약·정산의 실서비스 왕복은 실행하지 않았다. 이 부분은 사용자 생성
버튼 실행 전까지 미확인이다. 자동 테스트도 추가하거나 실행하지 않았다.

기존 8765 모니터 및 수집기를 재시작하지 않고 8766에 별도 미리보기를 열었다.
미리보기의 PID/이력/로그는 `runtime/recommendation-preview`로 분리했다.
기존 서버에 새 API를 적용하려면 모니터를 재시작해야 하며, 이는 현재
중단해 둔 다른 모니터 변경도 함께 로드하므로 이번 작업에서는 수행하지 않았다.

### 후속 적용 (사용자 요청 재개)

사용자가 웹 경고 해제와 Android 깜빡임 수정을 재개하도록 요청하여, 이 작업을
마친 뒤 22:10에 모니터 서버만 다시 실행했다. 추천 탭은 이제 기존 주소
`http://127.0.0.1:8765/recommend.html`에서 제공한다. 8766 미리보기 서버는
해당 스크립트 소유 PID를 확인하고 종료했다. 수집기 PID 1812는 유지했다.

### 추천 캐시와 영상 길이 추가

시각화의 IndexedDB 트랜잭션 코드를 `workspace-cache.js`로 공유하고 기존
시각화 DB 이름/store/key는 유지했다. 추천은 별도 DB의 마지막 workspace를
저장한다. 복원은 읽기 전용 참고 스냅샷이며 새 생성 전 검색이 필요하다.
전송 동의는 복원하지 않고, 진행 작업은 ID 조회만 재개한다. 삭제는 모달
확인을 거치며 원본 자료를 변경하지 않는다.

참고 자료에 수집 영상 길이와 분석 장면 종료 기준 근사 길이를 구분해 추가했다.
Gemini 응답 계약은 `duration_seconds`(5~180 정수), `duration_reason`, 각 장면의
`start_second`/`end_second`를 요구한다. 0부터 전체 길이까지 연속되지 않는
응답은 성공으로 처리하지 않는다. 이 범위는 초기 기획 제약이며 플랫폼 제한이나
최적 성과 길이의 검증 결과가 아니다.

브라우저에서 실제 참고 사례 6개(길이 확인 4개)를 검색한 뒤 새로고침하여
입력과 자료·길이의 복원을 관찰했다. 기존 시각화도 19:05 저장된 CSV와
3차 수집/공유 필터가 그대로 복원됐다. 생성 결과 캐시는 코드 검토 범위이며,
실제 Gemini 생성이나 자동 테스트는 이번에도 실행하지 않았다.

### 지정 분석 파일로 전환 (2026-10-24)

사용자가 지정한 `collectors/data/collector/fashion_reel_analyses.json`을
`collectors/data/collector/reel_analysis.json`으로 이름 변경했다. 변경 전후
122건, 2,311,643바이트와 SHA256
`e8a0bf78a197c86feeb672e276cfefdf88db8f60fb210befbe594251b87a9e78`이 일치했다.
변경 전 파일은 `.datasets/fashion/diagnostics/analysis_rename_20261024/`에
백업했고 같은 폴더의 `result.json`에 적용 내역을 기록했다.

수집기 PID 1812를 재시작하지 않고 실행 중인 분석 함수의 파일명 상수와
대기 중인 분석 코루틴의 출력 경로만 전환했다. 파일 사용 중인 스레드나
기존 경로로 실행 중인 insights 코루틴이 있으면 변경을 거부하도록 가드했다.
이후 실행을 위한 `reels/fashion_analyzer.py`와 README의 저장/입력 경로도
같이 변경했다. 모니터 서버만 재시작했다.

추천은 해당 JSON의 분석 레코드만 검색한다. 브라우저에서 예시 조건으로
122개 분석 릴스 중 6개 사례를 찾았고, 길이는 6개 모두 분석 장면 기준
근사값으로 표시됐다. 파일에 없는 조회/좋아요/저장 수치는 `—`로 표시한다.
이전 자료로 검색한 캐시는 새 검색 전 생성에 사용할 수 없으며 이전 기획안은
스냅샷으로 유지한다. 실제 Gemini 생성과 자동 테스트는 실행하지 않았다.

### 선택 입력 항목 (2026-10-24)

분위기 필수 입력을 제거하고 핵심 소구점(`selling_point`), 제작 조건
(`production_constraints`)을 각각 200자 이내 선택 입력으로 추가했다.
비어 있는 선택 항목은 서버에서 생략한다. 소구점은 유사 사례 검색에 반영하고,
제작 조건은 부정 표현을 키워드로 오해하지 않도록 Gemini의 촬영 구성에만
전달한다. 영상 형식은 모델이 사례에 맞게 제안한다. 기존 캐시의 기획안과
검색 결과는 유지하되 새 검색에는 이전 분위기를 전달하지 않는다.

Python/JavaScript 문법 확인과 독립 소스 검토를 마쳤다. 실제 브라우저에서
이전 분위기 캐시가 열렸고, 선택 항목을 모두 비운 검색과 두 항목을 채운
검색이 각각 6개 사례를 반환했다. 새로고침 뒤 선택 입력값·참고 사례가
캐시에서 복원됐다. 모니터만 재시작했으며 실제 Gemini 생성과 자동 테스트는
실행하지 않았다. 선택 조건이 모델 출력에 반영되는 실서비스 결과는 미확인이다.
